# Research Conclusions

## Use directly

### Anthropic frontend-design

Use for aesthetic direction and anti-generic frontend implementation. It is strongest at forcing purpose, tone, constraints, differentiation, typography, color, motion, spatial composition, and atmospheric detail.

### Anthropic webapp-testing

Use for real-browser verification with Playwright, screenshots, console inspection, and interaction checks.

### Vercel React best practices

Use for React/Next.js performance, waterfall prevention, bundle control, rendering, and client/server boundaries.

### Vercel Next.js best practices

Use for framework correctness and Next.js 16 conventions.

### Vercel web-interface review

Use as a broad UI review source, but pin or vendor the guideline file instead of fetching mutable `main` instructions forever.

## Adapt, do not install unchanged

### Trystan design-system prompt

Use its phased procedures:
- context/discovery
- design-system extraction
- aesthetic direction
- wireframe/variations
- accessibility review
- hierarchy/rhythm review
- interaction-state pass
- AI-slop check
- polish pass

Do not install the entire system prompt unchanged because it assumes HTML-artifact workflows, frequently requests 3+ variations, and prefers one file with toggles. Those rules conflict with the approved four-route Next.js architecture.

### Aura skills

Use Aura as a pattern catalogue, not an automatic trust source. The most useful ideas are:
- token and component system generation
- mobile-first/touch thinking
- high-agency composition
- micro-detail refinement

Community skills may include arbitrary hard bans and unknown licensing. Review each one before adapting.

## Recommended project pattern

Use one router skill plus focused specialist skills. Keep the router description broad enough to trigger for all portfolio UI tasks, then load only the matching specialist procedures. This reduces duplicated instructions and context load while ensuring mandatory review gates.
