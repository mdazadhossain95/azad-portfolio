# Portfolio UI Router

Read the repository instructions and current task before editing.

## Route the request

| Request | Load next |
|---|---|
| New version, redesign, hero, section, layout, visual concept | `../portfolio-design-direction/SKILL.md` |
| Tokens, colors, type, spacing, reusable components | `../portfolio-design-system/SKILL.md` |
| Layout exploration before implementation | `../portfolio-wireframe/SKILL.md` |
| Next.js/React implementation | `../portfolio-frontend-build/SKILL.md` |
| Accessibility or keyboard review | `../portfolio-accessibility-review/SKILL.md` |
| Hover/focus/loading/motion review | `../portfolio-interaction-review/SKILL.md` |
| Generic AI-template or visual-trope review | `../portfolio-ai-slop-review/SKILL.md` |
| Final visual refinement | `../portfolio-polish-gate/SKILL.md` |
| Browser rendering, screenshots, responsive or console verification | `../portfolio-browser-qa/SKILL.md` |

## Mandatory workflow

For a substantive visual change:

1. Load design direction.
2. Load design system.
3. Build a low-cost skeleton or wireframe.
4. Implement.
5. Run accessibility and interaction reviews.
6. Run the AI-slop review.
7. Run the polish gate.
8. Verify in a real browser.
9. Run lint, typecheck, tests, and production build.
10. Stop and report evidence.

Read:

- `../_shared/references/brand-system.md`
- `../_shared/references/version-directions.md`
- `../_shared/references/quality-gate.md`

Do not skip review stages because the page looks acceptable in source code.
