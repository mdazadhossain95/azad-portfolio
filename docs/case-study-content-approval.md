# Case Study Content Approval Rules

All case studies in this portfolio follow strict guidelines for content accuracy, evidence, and client confidentiality.

## 1. Verified Evidence Only
Claims, results, and metrics must be backed by evidence levels:
- `public`: Publicly verifiable via a live URL, store link, or open-source repository.
- `client-approved`: Specific numbers or statements approved by the client for public use.
- `private`: Non-specific statements regarding internal systems. No exact metrics or revenue numbers may be exposed.
- `unverified`: Claims without evidence are not permitted and should not be displayed.

## 2. Media Requirements
- **Real Screenshots**: Only use real, actual product screenshots. No fabricated screens or generic mockups.
- **Accessibility**: All media must have descriptive `alt` text.
- **No Autoplay**: Video media must not autoplay sound.
- **Data Privacy**: Ensure no PII (Personally Identifiable Information) or sensitive client data is visible in screenshots.
- **Responsiveness**: Images must be optimized and loaded in responsive sizes.

## 3. Confidential Projects
- Internal metrics, user volumes, and proprietary algorithms are strictly confidential.
- Project details should focus on individual contributions, technical decisions, and architecture rather than business secrets.
- Use `confidentialityNote` to clearly state what information has been omitted for privacy reasons.
- No direct source code is published unless explicitly open-sourced.

## 4. Approval Checklist
Before publishing a new case study, confirm:
- [ ] Store links are correct and independent.
- [ ] No unapproved claims or fabricated outcomes are included.
- [ ] Media dimensions are specified to avoid layout shift.
- [ ] Edge cases and technical decisions accurately reflect the developer's ownership.
- [ ] Contact CTA is present.
